# Scoopy Matter Milestone 1 Design

## Scope

Build a separate experimental Matter firmware under `firmware/matter/` while leaving `firmware/esphome/` completely untouched.

Milestone 1 ends when:

1. An ESP32-C3 Scoopy boots the new firmware.
2. Home Assistant commissions it over Matter-over-Wi-Fi using BLE rendezvous.
3. Button 1 on GPIO2 emits standard Matter Generic Switch events usable in Home Assistant automations.

Button 2, LD2410C presence, LEDs, recovery UX and Matter OTA are intentionally out of scope until this milestone works.

## Toolchain

- ESP-IDF 5.5.5
- ESP-Matter 1.6.0, pinned through the ESP-IDF Component Manager
- Target: ESP32-C3
- Flash: 4 MB
- Host: Ubuntu 22.04 under WSL2, normally driven from VS Code

## Firmware boundary

The Matter firmware is a standalone ESP-IDF project at `firmware/matter/`. It does not include, modify or depend on `firmware/esphome/`.

Application boundaries for Milestone 1:

- `app_main.cpp`: boot orchestration only
- `scoopy_matter.*`: Matter node/endpoints/events
- `scoopy_buttons.*`: GPIO input, debounce and gesture detection

Hardware input code must not call ESP-Matter APIs directly. Button code reports application-level actions; the Matter layer translates those actions into Generic Switch events.

## Matter model

- Endpoint 0: mandatory Root Node
- Endpoint 1: Generic Switch for Button 1

Button 1 uses the standard Matter Switch cluster with Momentary Switch, Action Switch and Momentary Switch Multi-Press features. No custom clusters are introduced.

The commissioning-only first build creates Endpoint 1 but does not yet connect GPIO2. The next incremental change connects the physical button to that already-stable endpoint.

## Commissioning

Scoopy is Matter-over-Wi-Fi. BLE is used only for commissioning rendezvous. Development/test Matter commissioning credentials are used initially.

The firmware should log commissioning lifecycle events and expose the ESP-Matter console during development so onboarding codes and network state can be inspected from serial.

## Flash layout

Use a 4 MB custom partition table from the start with two approximately 1.875 MiB OTA application slots. Matter OTA functionality remains disabled for Milestone 1, but the layout avoids a later repartitioning migration.

Persisted Matter/Wi-Fi state lives in NVS. Development testing should use `erase-flash` before the first Matter flash, then normal flashes thereafter unless deliberately testing factory-reset behaviour.

## Build/reproducibility

`espressif/esp_matter` is pinned to exactly `1.6.0`. Generated `managed_components/`, `build/` and local `sdkconfig` files remain untracked. The dependency lockfile generated by the first successful build should be committed.

## Test gates

Commissioning gate:

- clean build for ESP32-C3
- firmware image reports 4 MB flash configuration
- flash/monitor succeeds over `/dev/ttyACM0`
- serial log shows Matter stack and commissioning window
- development onboarding code can be obtained
- Home Assistant commissions the node successfully

Button 1 gate:

- GPIO2 configured input/pull-up/active-low
- debounce is handled outside Matter code
- single, double and hold gestures are distinguishable
- standard Generic Switch events reach Home Assistant
- no changes occur under `firmware/esphome/`
